# 泽玮 OS 知识库构建

## 触发条件

当用户需要把一组已授权资料组织成可追溯、可检索、可更新的泽玮 OS 知识库时使用。若只是回答一个问题、摘要单份材料或同步未经授权的私有来源，不使用本技能。

## 输入

需要知识库目标、授权来源清单、目标用户、访问边界、更新频率、输出位置和已有分类。每个来源至少应有来源标识、标题、位置、所有者或发布者、获取日期和使用限制。

## 执行步骤

1. 确认范围、读写权限、排除内容和完成标准；为个人信息与受限材料定义隔离规则。
2. 为来源、知识条目和术语设计稳定标识，避免用可变文件名作为唯一身份。
3. 设计最小分类、标签、别名和归类规则；无法判断的条目进入待裁定区，不强行归类。
4. 将来源清单标准化为清单文件，记录位置、摘要哈希、日期、许可或访问限制、状态和替代关系。
5. 生成条目索引与来源映射；每个可发布主张必须能回到至少一个来源记录。
6. 对冲突内容并列记录主张、来源、日期和适用范围，不用多数票掩盖冲突。
7. 定义新鲜度规则、复核负责人和过期动作；对失效链接、无日期来源和被替代内容单独标记。
8. 验证标识唯一性、引用完整性、内部链接、权限边界和增量更新路径。

## 输出

输出知识库目录、来源清单、分类与术语表、条目索引、冲突清单、新鲜度策略和验证报告。结构可按目标载体调整，但来源标识和审计字段必须保留。

## 权限与边界

默认只对用户授权的材料和目标目录操作。不把第三方许可证改写为本仓库许可，不把私有原文复制到公开位置，不主动删除旧资料。外部知识库写入、权限变更和公开发布遵循目标系统授权。

## 失败处理

来源权限不明时只生成待核实清单；分类无法稳定时先使用浅层分类；目标系统不可用时生成可导入的中间清单并保留未执行状态。

## 验证方法

使用授权来源集合、混合权限来源、包含冲突与失效链接的集合三类合成用例验证。检查来源可追溯、权限隔离、冲突保留和增量更新；证据保存在 `evals/zeve-knowledge-base-builder/`。
