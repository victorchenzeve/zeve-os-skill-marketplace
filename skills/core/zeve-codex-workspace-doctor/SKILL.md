# Codex 工作区诊断

## 触发条件

当用户需要排查 Codex 工作区、Skill Marketplace、插件注册、依赖、配置或发行检查失败时使用。若请求只是编写业务内容或要求未经审查地自动修复系统环境，不使用本技能。

## 输入

需要工作区路径、失败现象、复现步骤、相关日志、期望行为和允许检查的范围。缺少日志或无法复现时，先明确可观察事实与待验证假设。

## 执行步骤

1. 确认诊断范围、当前版本、运行环境与可接受的停机或变更边界。
2. 只读采集目录结构、注册关系、版本、配置引用、依赖可用性和失败输出，避免显示密钥或用户数据。
3. 用最小复现把症状定位到资产、配置、依赖、权限、网络或工具链层，并记录支持与反驳证据。
4. 按影响、置信度、可逆性和验证成本排列可能原因，不把相关性写成根因。
5. 为每个建议修复写出前置条件、具体改动、回滚方式和成功检查；需要写入、安装或外部动作时先交付可审查方案。
6. 在获得相应授权并执行修复后，重新运行最小复现和受影响的完整检查，记录结果与剩余风险。

## 输出

输出环境摘要、症状与证据表、根因判断及置信度、优先修复计划、回滚步骤、验证命令或检查项，以及未解决问题。敏感值只报告存在性和作用域，不输出内容。

## 权限与边界

默认仅做只读诊断，不修改配置、不安装依赖、不终止进程、不删除文件、不推送或发布。任何写入或外部操作都必须处于用户已授权的任务范围。诊断结果不替代平台服务状态或供应商支持结论。

## 失败处理

无法访问路径时列出所需的最小证据；命令不可用时提供替代检查；问题无法复现时保留时间、环境和差异条件；多个原因仍可能成立时不强行选定单一根因。

## 验证方法

使用注册表计数漂移、依赖缺失、包含敏感日志三类合成用例验证。检查只读默认、证据分层、修复可回滚和验证闭环；证据保存在 `evals/zeve-codex-workspace-doctor/`。
