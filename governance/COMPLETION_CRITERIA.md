# Marketplace 完成标准

项目的“完成”按可持续运营能力判断，不以把所有本机或飞书 Skill 自动搬进仓库为目标。

## 仓库内完成条件

1. 正式资产具有可验证的结构、唯一注册、显式依赖、来源、许可和评估证据。
2. Codex Marketplace 与独立 CLI 均能从发行包安装，并保护本地修改。
3. CI 检查注册、Inventory、候选队列、插件镜像、测试和发行包。
4. 盘点差异转成可追踪队列，且不会自动修改来源资产或外部系统。
5. 版本、变更记录、治理决策和运营状态保持一致。

## 需要外部证据的持续事项

- 领域 Skill 从 `experimental` 晋级 `stable`，必须使用获准的真实业务材料，并满足成熟度模型的成功、失败和依赖不可用证据要求。
- 飞书重复或遗漏记录的实际修改，需要表所有者确认每条处理决定并明确授权写入。
- 第三方 Skill 只有在来源、许可证和再分发权核实后，才能进入正式 Registry。

这些事项是治理流程的正常输入，不是用合成材料可以消除的工程缺陷。
