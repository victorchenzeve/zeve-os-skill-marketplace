# 决策记录

## 2026-09-09：建立统一治理仓库

- 保留用户指定的目录结构，在已有空 Git 仓库中落地。
- 正式注册表与盘点清单分开；不自动导入本机已安装技能。
- YAML 文件采用兼容 YAML 1.2 的 JSON 写法，以 Node.js 内置能力完成校验，免去依赖安装。
- 插件采用内部描述格式，未来接入宿主时新增专门适配，不宣称开箱可安装。
- 初始注册表留空，私域插件目录仅占位；示例只放模板目录。
- 暂不确定开源许可证及发布平台，待所有者明确后补充。

## 2026-09-10：执行存量技能只读盘点

- 按所有者明确要求扫描已安装及本地创建来源，不改 Skill、不合并、不删除；正式注册表继续为空。
- 区分文件位置、运行时发现、启用状态和来源证据。独立 app-server 的插件发现结果不代表所有桌面任务。
- 记录每个路径、正文 SHA-256、声明元信息、生成记录和结构观察。作者归属和成熟度不自动认定。
- 使用快照和三个可重叠视图，原始本机路径映射保留在忽略提交的 `.tmp/`。

## 2026-09-13：发布 1.0.0 Marketplace

- 采用“正式源文件 + 插件发行镜像”结构：`skills/` 是唯一正式源，插件 `skills/` 由同步工具生成并做字节一致性校验。
- 首发只纳管本仓库新建且明确采用 MIT 的资产，不从 Inventory 自动复制第三方或本机 Skill。
- 同时提供 Codex 原生 Marketplace 插件安装与独立 Skill CLI 安装；两条路径均在隔离目录完成真实安装验证。
- 安装器使用所有权回执和目录哈希保护本地修改；覆盖或删除变化内容必须显式使用 `--force`。
- 仓库版本进入 `1.0.0`。首发业务资产保持 `experimental`，真实业务评估完成后再升为 `stable`。
- Git Tag `vMAJOR.MINOR.PATCH` 触发发行制品构建和 GitHub Release；远端配置与首次推送仍由所有者针对具体目的地授权。
- MIT 只覆盖仓库原创代码、文档和明确标注的首发资产；Inventory 不改变第三方资产权利。

## 2026-09-14：完成首批领域纳管与品牌前缀统一

- 首批规模固定为 20 个 Skill、4 个领域插件和 4 个代理；领域覆盖私域、内容、知识与研究，两个 Core Skill 独立提供市场治理能力。
- 所有新增资产均为仓库原创 MIT 资产，不从本机 Inventory 或第三方安装目录复制正文。
- 英文品牌前缀由旧的 `zewei` 统一迁移为 `zeve`；Skill ID 校验禁止旧前缀，插件、Marketplace、CLI 和包名同步迁移。中文品牌继续使用“泽玮 OS”。
- 保留 1.0 安装回执兼容读取，写入时迁移到新回执名，避免已安装用户失去所有权保护。
- 仓库版本升级为 1.1.0；首批领域资产保持 `experimental`，等待真实业务评估后按单项升级。

## 2026-09-14：建立持续治理闭环并扩展业务领域

- Registry Schema 升级为 2.0.0，正式资产必须在唯一索引中登记许可证、来源分类、所有者、复核日期、评估状态和证据路径。
- 新增五个原创业务决策 Skill、一个插件和一个代理；不从本机 Inventory 或飞书表复制第三方正文。
- 两个 Core Skill 已实际用于本仓库的候选审查、品牌迁移、注册校验和远程发行，使用仓库证据晋级 `stable`；领域能力仍需真实业务结果才能晋级。
- 飞书审计异常进入可重复生成的 58 项候选队列。队列只表达待核对动作，不自动修改表、Skill、安装状态或正式 Registry。
- 每周 CI 复验治理一致性和发行包安装。真实业务评估、第三方许可核实与飞书实际写入继续作为有责任人的运营输入。
